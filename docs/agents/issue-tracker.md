# Issue tracking

Public Camenya work lives in GitHub Issues. The issue and pull-request templates define the information required for community work; `docs/community/issue-labels.md` defines label meaning and readiness.

Agents may keep temporary planning notes under `.scratch/`, which Git ignores. These notes are local working memory: they are not a source of project truth, a substitute for an issue, or part of a public release.

Before implementation, ensure the public issue states the user problem, smallest useful outcome, non-goals, acceptance criteria, and prerequisites. Record durable decisions in the appropriate tracked document, not in `.scratch/`.
