# Domain documentation

This repository uses a single domain context.

Before changing behavior:

1. read `CONTEXT.md`;
2. read relevant decisions under `docs/adr/`;
3. use the canonical terms from the glossary in code, tests, and tickets;
4. surface any ADR conflict instead of silently overriding it.

`CONTEXT.md` contains vocabulary only. Architectural trade-offs belong in ADRs.
